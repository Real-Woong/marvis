# Marvis × Stack Chan

- 상태: 아이디어 → 방향 정리됨 (2026-09-17, 구현 전)
- 기록일: 2026-09-16
- 출처: 사용자 채팅

## 아이디어

Telegram 기반 개인 AI 비서 Marvis를 Stack Chan에 탑재해, 화면·표정·음성이 있는 실물 비서 디바이스로 확장한다.

## 기대 효과

- 알림과 아침 브리핑을 텔레그램 밖에서도 상시 확인할 수 있다.
- 음성 입출력과 표정을 붙여 Marvis의 비서 캐릭터를 강화할 수 있다.
- 기존 `core.py`를 유지하고 Stack Chan을 새 입출력 채널로 붙이는 구조를 검토한다.

## 검토 필요

- 하드웨어 버전과 통신 방식(HTTP, WebSocket, MQTT 등)
- Mac mini와 디바이스 사이의 인증·재연결·오프라인 동작
- Marvis 응답과 표정·음성·화면 상태의 매핑
- 상시 대기 전원, 마이크 프라이버시, 물리 음소거 방식

## 기기 확인 (2026-09-17)

`Stack-Chan/STACK_CHAN_Usage_Guid.md` 기준.

- M5Stack 공식 StackChan. CoreS3(ESP32-S3, 8MB PSRAM), 2.0" 터치 LCD, 듀얼 마이크 + 1W 스피커, 0.3MP 카메라, 2축 서보(Y축 5°~85°), 550mAh 배터리, Wi-Fi 2.4GHz 전용.
- 순정 AI Agent는 XiaoZhi 기반이고 설정은 StackChan World 앱에서 한다. 기기 쪽 LLM(qwen 등)과 음성(STT/TTS)은 기기 클라우드가 담당한다.
- 가이드에 "Home Assistant MCP 연동" 언급이 있다 → 순정 상태에서도 외부 도구를 붙일 여지가 있다. **앱에서 임의의 MCP 서버를 등록할 수 있는지는 아직 확인 안 함.**
- 순정 펌웨어(앱 설정)와 xiaozhi.me 기반 펌웨어는 서로 호환되지 않는다. 경로를 바꾸면 재설정이 필요하다.

## 방향

**Marvis를 기기에 옮기지 않는다. 맥미니의 Marvis는 그대로 두고, Stack Chan을 텔레그램·Siri에 이은 세 번째 입출력 채널로 붙인다.** ESP32에 Python·SQLite·`_STATUS.md` 되쓰기를 올릴 이유가 없고, Siri 웹훅이 이미 "외부 입력 → `core.handle_message`" 구조를 증명했다.

판단 기준은 [[marvis-purpose-is-load-reduction]]: 감시할 데몬, 외울 명령, 관리할 펌웨어가 늘지 않는 순서로 간다.

### 단계

| 단계 | 내용 | 펌웨어 | 새로 관리할 것 |
|---|---|---|---|
| 0. 확인 | StackChan World 앱에서 외부 MCP 서버(엔드포인트) 등록이 되는지, 기기가 맥미니에 닿는지(같은 LAN / Tailscale 불가 시 대안) | 순정 | 없음 |
| 1. 조회 (pull) | "오늘 할 일 뭐야?", "프로젝트 뭐 남았어?"에 기기가 답한다. Marvis 쪽에 **읽기 전용** MCP 도구 2~3개(오늘 할 일, 진행중 프로젝트, 다음 일정)만 노출 | 순정 | MCP 엔드포인트 하나 (기존 봇 프로세스 안에서 띄운다, 별도 데몬 X) |
| 2. 저장 (write) | "내일 3시 치과 기억해줘"를 기기로 넣는다. 도구를 잘게 쪼개지 말고 `handle_message(text, source="stackchan")` 통과 도구 하나로 둔다 | 순정 | 없음 |
| 3. 먼저 말 걸기 (push) | 아침 브리핑·시각 알림을 기기가 표정과 함께 읽는다 | 커스텀 가능성 높음 | 펌웨어 빌드·업데이트 |

### 순서를 이렇게 잡은 이유

- **처음 제안한 "단방향 알림 표시"가 사실 가장 어렵다.** 순정 에이전트는 사람이 말을 걸면 도구를 부르는 구조라, 맥미니가 기기를 먼저 깨우는 경로가 기본으로 없다. push는 커스텀 펌웨어나 XiaoZhi 서버 자가 호스팅 쪽으로 가야 할 가능성이 높다. 그래서 pull을 먼저 한다.
- **뇌가 두 개가 된다.** 발화 해석은 기기 쪽 LLM이 하고 Marvis는 도구가 된다. 이건 지금 shadow로 묶어 둔 LLM 라우터와 같은 위험(말만 하고 안 함, 몰래 씀)을 기기 쪽 LLM으로 다시 여는 것이다 — [[telegram-features-need-the-regex-route]]. 그래서 1단계는 읽기 전용, 2단계 쓰기는 정규식 경로를 그대로 타는 `handle_message` 통과 하나로 두고, 답은 다시 읽어 확인한 값을 돌려준다.
- **쓰기는 텔레그램에도 남긴다.** Siri 웹훅처럼 기기로 저장한 내용을 텔레그램에 한 줄 복사해, 잘못 알아들은 저장을 바로 발견할 수 있게 한다.

### 하지 않을 것 (지금은)

- 카메라·얼굴 추적·댄스 등 Marvis 목적(부담 줄이기)과 무관한 기능 연결
- 1~2단계가 안 되는데 바로 커스텀 펌웨어로 가는 것 — 그 전에 "기기 없이 텔레그램으로 충분한가"를 먼저 다시 묻는다

## 검토 필요 (갱신)

- [ ] StackChan World 앱의 MCP 등록 가능 여부와 방식(기기 → 클라우드 → 내 서버인지, 내 서버가 바깥으로 연결하는지)
- [ ] 기기 쪽 클라우드로 일정·프로젝트 내용이 넘어가는 것을 받아들일지 (프라이버시)
- [ ] 한국어 STT가 "기억해줘"·날짜 표현을 얼마나 원문 그대로 넘기는지 — 저장 파서가 원문에 기대고 있다
- [ ] 상시 대기 전원(550mAh라 거의 USB 상시 연결 전제), 마이크 음소거 방법
- [ ] 커스텀 경로 참고: stackchan-mcp(XiaoZhi 기반 StackChan용 MCP 게이트웨이), M5Stack 공식 펌웨어 빌드 문서

Stack Chan 화면에 Marvis의 단방향 알림 하나를 표정과 함께 표시하는 최소 프로토타입으로 통신 지연·재연결·가독성을 확인한다.
