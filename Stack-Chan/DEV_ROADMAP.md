
## 규칙

1. **건너뛰지 않고 줄인다.** 바쁜 주는 30분짜리 한 걸음이라도 한다. "고개 한 번 돌리기 성공"도 한 편이다.
2. **안 되면 그게 그 주의 편이다.** 실패 장면과 원인을 찍고, 다음 주로 넘긴다.
3. **화면에 실제 데이터를 내보내지 않는다.** 일정·프로젝트명·텔레그램 대화·`.env`·로그가 찍히지 않게 촬영용 데모 데이터를 쓴다.
4. **Marvis 본체 규칙을 지킨다.** 쓰기는 정규식 경로(`handle_message`)로만, 답은 다시 읽어 확인한 값으로. 기기 쪽 LLM이 "저장했어요"라고 말만 하는 일이 없게 한다.
5. **목적과 무관한 기능은 콘텐츠용으로 따로 둔다.** 댄스·얼굴 따라하기는 찍어도 되지만 Marvis 경로에 섞지 않는다.
6. **토요일 끝에 아래 기록표에 한 줄.** 막힌 게 있으면 DEV_LOG에도 남긴다.

## 로드맵

W0 결과(순정 앱에 외부 MCP 서버를 붙일 수 있는가)에 따라 W1부터 경로가 갈린다.
W5 이후는 앞 결과를 보고 다시 짠다.

### 1부 — 말을 걸면 답한다 (순정 펌웨어)

| 주 | 토요일 목표 | 끝났다는 기준 | 일요일 릴스 |
|---|---|---|---|
| **W0** | 언박싱, 앱 바인딩, 서보 보정, **MCP 등록 가능 여부 확인** | 기기가 대화되고, 경로 A/B 중 하나로 결정 | 언박싱 + 처음 고개 드는 순간 |
| **W1** | 기기 → 맥미니 연결. 고정 문장만 돌려주는 `hello` 도구 하나 | "Marvis 불러줘" → 내 서버가 준 문장을 기기가 말함 | 로봇이 처음으로 *내 코드*의 말을 함 |
| **W2** | 조회 도구: **오늘 할 일** (읽기 전용) | "오늘 할 일 뭐야?" → 텔레그램 브리핑과 같은 내용 | 텔레그램 봇이 몸을 얻었다 |
| **W3** | 조회 확장: 진행중 프로젝트, 다음 일정 + **촬영용 데모 데이터** | 데모 데이터로 세 질문 모두 답함 | "프로젝트 뭐 남았어?" |
| **W4** | 저장: `handle_message(text, source="stackchan")` 통과 도구 하나 + 텔레그램에 한 줄 복사 | 말로 저장 → 텔레그램에 같은 값이 보임, 오인식 사례 기록 | 말로 저장, 화면 두 개 나란히 |

### 2부 — 먼저 와서 알린다

| 주 | 토요일 목표 | 끝났다는 기준 | 일요일 릴스 |
|---|---|---|---|
| **W5** | 재촉 로직을 **텔레그램으로 먼저**: 알림 후 N분 지나도 `done=0`이면 한 번 더 (일정당 최대 1~2회) | 테스트 통과 + 실제로 한 주 써봄 | 로봇보다 뇌부터 (재촉 설계) |
| **W6** | **push 경로 조사·결정**: 커스텀 펌웨어 / XiaoZhi 서버 자가 호스팅 / stackchan-mcp 게이트웨이 | 한 경로로 결정하고 이유를 IMPROVE에 적음 | 로봇이 먼저 말 걸게 하는 게 왜 어려운가 |
| **W7** | 알림 시각에 **고개 돌리고 표정 + 말 걸기** | 리마인더 루프 → 기기 반응 한 번 성공 | 강아지 같은 첫 순간 |
| **W8** | 재촉을 기기로: **쳐다보기 → 표정 → 말 → 텔레그램** 단계 | 완료 안 한 일정에 단계대로 반응 | 안 하면 재촉하는 로봇 |
| **W9** | 자리 감지: 근접 센서로 **자리에 있을 때만** 말 걸기 | 자리 비움이면 텔레그램으로 대신 보냄 | 내가 없으면 기다리는 로봇 |

### 3부 — 나중에 (정하지 않음)

- 토요일 개발 알림을 로봇이 직접 하기 ("나를 만들러 와")
- 아침 브리핑을 기기가 읽기
- 카메라로 딴짓 감지 — 감시 범위와 프라이버시를 먼저 정한 뒤에만
